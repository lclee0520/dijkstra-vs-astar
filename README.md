## 📌 개요

**"가중치 그래프에서 출발점부터 목표점까지 최단 경로 찾기"** 라는 같은 문제를 Dijkstra와 A*로 풀고, 두 알고리즘의 내부 동작을 같은 그래프 위에서 단계별로 나란히 보여 주는 웹앱입니다.

둘 다 최단 경로를 찾지만 **A*가 훨씬 적은 정점만 꺼내고 끝냅니다.** 두 코드는 우선순위를 계산하는 한 줄만 다릅니다.

```
Dijkstra: 우선순위 = g(n)          // 출발점부터 지금까지 실제 비용
A*:       우선순위 = g(n) + h(n)   // 실제 비용 + 목표까지 남은 거리 추정치
```

h(n)은 목표까지의 직선거리입니다. h가 실제 남은 거리보다 크지 않아야 최단 경로가 보장되며, 일부러 h를 과대평가한 반례 모드도 함께 제공합니다.

## 🗺️ 예제 그래프

정점 7개 무방향 가중치 그래프입니다. 출발은 S, 목표는 G이고 우선순위가 같으면 알파벳순으로 꺼냅니다.

```
        C ──3── F
        │        ╲
        3         5
        │          ╲
 B ─2── S ───4── A ──4── G
        │
        2
        │
        D
```

| 정점 | 좌표 | h (G까지 직선거리) | 비고 |
|---|---|---|---|
| S | (0, 0) | 6 | 출발 |
| A | (3, 0) | 3 | 최단 경로 위 |
| G | (6, 0) | 0 | 목표 |
| B | (-2, 0) | 8 | 목표 반대쪽 막다른 길 |
| D | (0, -2) | 6.3 | 목표와 상관없는 방향의 막다른 길 |
| C | (0, 3) | 6.7 | 우회로 |
| F | (3, 3) | 4.2 | 우회로 |

간선: S-A 4, A-G 4, S-B 2, S-D 2, S-C 3, C-F 3, F-G 5

- 모든 간선 가중치가 두 정점 사이 직선거리 이상이므로 h는 실제 남은 거리를 넘지 않습니다.
- h 값은 소수 둘째 자리에서 반올림했습니다 (C 6.708, D 6.325, F 4.243).

## ⚙️ 핵심 의사코드

```
SEARCH(G, s, t)
    g[s] = 0;  PQ.insert(s, 우선순위(s))
    while PQ not empty
        u = PQ.extractMin()          // 우선순위가 가장 작은 정점
        if u == t: return path(parent, t)
        for (v, w) in adj[u]
            if g[u] + w < g[v]       // 더 짧은 길을 찾았으면
                g[v] = g[u] + w;  parent[v] = u
                PQ.insertOrDecrease(v, 우선순위(v))

우선순위(v):  Dijkstra → g[v]
              A*       → g[v] + h[v]
```

## 📊 실행 결과 비교

| 항목 | Dijkstra | A* (정상 h) | A* (h(A) = 10, 반례) |
|---|---|---|---|
| 찾은 경로 | S → A → G | S → A → G | S → C → F → G |
| 거리 | **8** (최단) | **8** (최단) | **11** (오답) |
| 꺼낸 정점 수 | 7개 | 3개 | 6개 |
| 발견한 정점 수 | 7개 | 6개 | 7개 |
| 꺼낸 순서 | S → B → D → C → A → F → G | S → A → G | S → D → C → B → F → G |

- **Dijkstra**: 목표 방향을 모르므로 막다른 길 B, D까지 출발점에서 가까운 순서대로 모두 확인합니다.
- **A\***: B는 g = 2로 가장 가깝지만 h = 8이라 f = 10이 되어 뒤로 밀립니다. 목표 쪽 A부터 펼쳐 3개만에 도착합니다.
- **반례**: h(A)를 실제 남은 거리 4보다 큰 10으로 두면 A의 f가 14로 부풀려져, 최단 경로를 보기 전에 우회로(거리 11)로 끝나 버립니다.
- **과대평가 ≠ 항상 오답**: h(A)가 4.5~7이면 과대평가지만 정답을 찾습니다. 대신 꺼내는 정점이 4~7개로 늘어납니다. A의 f가 우회로 비용 11을 넘는 순간(h(A) > 7)부터 오답이 됩니다.

## 📐 복잡도 비교

| 항목 | Dijkstra | A* |
|---|---|---|
| 시간 (이진 힙, 최악) | O((V + E) log V) | O((V + E) log V) |
| 공간 | O(V) | O(V) |
| 실제 탐색량 | 출발점 기준 동심원으로 전부 | h가 정확할수록 목표 방향만 |
| 최단 경로 보장 | 음수 간선이 없으면 보장 | h가 과대평가하지 않으면 보장 |
| 관계 | h = 0인 A*와 동일 | |

## ✨ 주요 기능

- **나란히 비교**: 같은 단계 번호에서 Dijkstra와 A* 상태를 좌우로 동시에 표시
- **단계 이동**: 처음 / 이전 / 다음 / 끝 버튼, 슬라이더, 자동재생, 키보드 ← →
- **단계별 설명**: 매 단계마다 "한 일"과 "이유"를 함께 표시
- **우선순위 큐 표시**: 큐에 든 정점과 우선순위 값(g 또는 f)을 작은 순서로 표시
- **g / h / f 표시**: 정점마다 현재 값을 표시하고, A*는 현재 정점에서 목표까지 직선(h)을 점선으로 표시
- **반례 모드**: A*의 h(A)를 10으로 과대평가했을 때 틀린 경로가 나오는 과정을 재생
- **h(A) 슬라이더**: h(A)를 0~12로 바꿔 가며 A*를 재생. 값별 결과를 색 띠로 표시 (h(A) ≤ 4 정상, 4.5~7 과대평가지만 정답, 7.5 이상 오답)
- **의사코드 하이라이트**: 현재 단계에서 실행된 줄을 강조
- **실제 실행 기반**: 단계 데이터를 손으로 적지 않고 Dijkstra/A* 코드를 실행하며 기록
